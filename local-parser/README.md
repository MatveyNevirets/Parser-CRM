# Локальный модуль импорта

Отдельный Node.js companion запускается пользователем на своём компьютере. Он реализует типизированный `ImportService`, открывает видимый Chromium через Playwright и сохраняет промежуточные пакеты в SQLite. Источник карточек — выдача 2ГИС в обычном браузере. React общается с процессом через небольшой loopback API на `127.0.0.1`; в будущей desktop-версии основной процесс сможет вызвать `LocalImportService` напрямую.

## Установка и запуск

Нужен Node.js 20 или новее. На первом запуске:

```powershell
npm --prefix local-parser install
npm --prefix local-parser run install:browser
npm run dev:connected
```

`dev:connected` запускает CRM на `http://localhost:5173` и парсер на `127.0.0.1:43127`, соединяя их автоматически. Это единый процесс запуска: отдельно запускать `dev` и `parser:local` в этом режиме не требуется. Повторный запуск обнаруживает занятые порты до создания новых служб. Для перезапуска остановите прежнюю команду через Ctrl+C.

Локальные запуски и карточки сохраняются в `%LOCALAPPDATA%\PahotaCRM\imports.sqlite`. Карточки записываются по мере обработки. Сбор выполняется в локальном процессе и продолжается после обновления страницы CRM. Интерфейс обновляет выбранный пакет каждые 20 секунд, сохраняя поиск, страницу и галочки. После перезапуска локального процесса незавершённый автоматический сбор восстанавливается в новом окне браузера с учётом сохранённых ID. При отдельном запуске `npm run parser:local` порт занимается до открытия SQLite. Если порт занят, вторая копия завершается до открытия базы.

Для разработки разрешены `http://localhost:5173` и `http://127.0.0.1:5173`. Для опубликованной CRM укажите точный HTTPS origin до запуска процесса:

```powershell
$env:PARSER_ALLOWED_ORIGINS = 'https://crm.example.com'
npm run parser:local
```

Процесс выводит временный pairing token. Введите его в экране «Парсер» той же вкладки браузера. Не публикуйте и не пересылайте его. Токен хранится в `sessionStorage` только текущей вкладки; Supabase ключ и access token в локальный процесс не отправляются.

## Границы доступа и обработка источника

- HTTP слушает только `127.0.0.1`, origin проверяется по точному allowlist, запросы требуют pairing token, ограничены размером и частотой.
- API не принимает URL, команду оболочки, путь к файлу или произвольный браузерный код.
- Playwright запускает обычный видимый браузер без прокси, изменения отпечатка или обхода защиты.
- CAPTCHA требует ручного решения в открытом браузере и нажатия «Проверить CAPTCHA и продолжить». Ограничение доступа останавливает сбор.
- Карточка с ошибкой загрузки сохраняется как непроверенная, после чего сбор переходит к следующей. Вкладка контактов при ошибке создаётся заново. Через 60 секунд без прогресса браузер перезапускается. Допускаются три автоматических перезапуска подряд без новых карточек. При пустой странице сбор переходит дальше, до пяти последовательных попыток.
- Количество `0` собирает до конца доступной выдачи с общим пределом 5000 карточек и 200 страниц. Порции по 20 страниц и 1000 карточек продолжаются автоматически.
- DOM выдачи 2ГИС может меняться; адаптер пока не подтверждён живым пробным запуском и не должен называться готовым рабочим парсером до такой проверки.
- Поиск запускается по строке «ниша + город» через веб-интерфейс 2ГИС. Если сайт не открыл результаты по указанному городу, проверьте регион и запрос в видимом окне браузера.

После явного подтверждения в веб-интерфейсе выбранные карточки передаются в существующую авторизованную Supabase-сессию. База повторно проверяет права, поля и дубликаты и возвращает отчёт; local SQLite обновляет локальные статусы. SQL миграция хранит только краткий idempotency report, не staging-пакет.

## Фильтр компаний с сайтом

Парсер открывает вкладку «Контакты» по каноническому адресу `/firm/{id}` и проверяет её несколько раз с ожиданием поздних ссылок. Отслеживающие ссылки 2ГИС распаковываются, в том числе формат `?http://company.ru`. Сайты на Tilda, Яндексе и Taplink учитываются как сайты. Telegram, Instagram, YouTube, VK, WhatsApp и другие известные соцсети и мессенджеры не учитываются при определении наличия сайта. Нераскрытые контакты, незавершённая загрузка или неизвестная структура дают `unknown`.

Флажок «Исключать, если есть сайт» включён по умолчанию. В этом режиме найденный URL или отметка `websiteCheckStatus = 'present'` исключает карточку. При снятом флажке сайт сохраняется в данных и карточка доступна для включения. Режим записывается в SQLite вместе с пакетом и передаётся на сервер при публикации. Старые пакеты используют фильтрацию сайтов. Незавершённая или устаревшая проверка допускает ручное включение.

Дубли проверяются внутри страницы, между страницами и по другим локальным пакетам той же команды. Более двух разных карточек с нормализованным названием в одном сборе удаляют всю группу из этого пакета, включая карточки с сайтом. Идентификаторы просмотренных карточек сохраняются для продолжения после перезапуска. Количество в настройках ограничивает число просмотренных исходных карточек. Подходящих результатов может быть меньше.

Для существующей CRM примените `202611180001_sales_workflows.sql`, затем `202611180002_sales_import.sql` из каталога `supabase/migrations`. Вторая миграция включает необходимые объекты ранних версий парсера. Перед отправкой интерфейс заново читает выбранные карточки. Supabase повторно проверяет фильтр сайтов, данные и дубли, включая карточки в архиве.

Во время сбора можно выбирать, редактировать и включать карточки, а также добавлять их кнопкой «Добавить карточку». Для публикации сбор нужно остановить или дождаться его завершения. Кнопка «Выбрать все не исключённые» ставит галочки во всём пакете независимо от страницы и поиска, включая непроверенные карточки. Ручной выбор позволяет вернуть вручную исключённую карточку. «Включить выбранные» сохраняет решение порциями до 100 карточек. Ошибки данных, дубли и филиальные группы требуют разрешения перед публикацией. Отклонённые и опубликованные пакеты закрыты для редактирования.

При подключении интерфейс проверяет `protocolVersion` локального процесса. Старая запущенная версия больше не подключается молча: интерфейс объясняет, что процесс нужно перезапустить. Кнопка «Проверить публикацию» открывает предварительный отчёт; добавление в общую CRM происходит по действию «Подтвердить и опубликовать». API сохранения отчёта возвращает обновлённый пакет в `{ run }`, который ожидает интерфейс. HTTP-регрессия проверяет включение, подготовку ключа и сохранение тестового отчёта у остановленного пакета в отдельной SQLite, без обращения к рабочей CRM.

`npm test` из корня проверяет SQL-миграции в изолированной PostgreSQL через PGlite, правила SQLite и чтение контактов в Chromium на локальных тестовых страницах. Браузерная регрессия проверяет весь путь найденного URL через сервис и SQLite до списка результатов и поля «Сайт» в редакторе, а также исключение таких карточек из массового включения. Рабочая CRM в тестах не используется.
