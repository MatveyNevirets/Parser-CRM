# Pahota CRM — веб-версия

Командная CRM на React + TypeScript + Vite. Данные хранятся в Supabase PostgreSQL, вход работает через Supabase Auth, а карточки синхронизируются через Supabase Realtime.

## Быстрый запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://127.0.0.1:5173`). При первом открытии приложение попросит `Project URL` и `Publishable key` проекта Supabase. Они и пользовательская сессия сохраняются локально в текущем браузере.

Для проверки production-сборки:

```bash
npm run build
npm run preview
```

Для совместного локального запуска CRM и парсера используйте одну команду:

```powershell
npm --prefix local-parser install
npm --prefix local-parser run install:browser
npm run dev:connected
```

Откройте `http://localhost:5173`. Команда запускает обе службы и автоматически подключает парсер; отдельный запуск `npm run dev` или `npm run parser:local` в этом режиме не требуется. Для перезапуска остановите прежнюю команду через Ctrl+C. Повторный запуск проверяет занятые порты и оставляет работающую связку на месте.

Для отдельного companion-процесса используйте `npm run parser:local` и введите напечатанный токен в CRM. Для опубликованного CRM сайта задайте точный HTTPS origin через `PARSER_ALLOWED_ORIGINS` перед запуском процесса. Оставьте процесс запущенным на время работы с разделом «Парсер»; он откроет видимое окно Chromium при сборе.

## Бесплатная настройка Supabase

1. Создайте один проект на бесплатном тарифе [Supabase](https://supabase.com/dashboard). Команда использует один проект на всех устройствах.
2. Откройте `SQL Editor`. Для нового проекта выполните SQL-файлы из [`supabase/migrations`](supabase/migrations) в порядке имён, начиная с `202610180001_team_crm.sql`.
3. Для обновления существующей CRM выполните [`202611180001_sales_workflows.sql`](supabase/migrations/202611180001_sales_workflows.sql), если она ещё не применена, затем [`202611180002_sales_import.sql`](supabase/migrations/202611180002_sales_import.sql). Миграция импорта включает необходимые объекты ранних версий парсера. Для выбора статуса «Оффер» также нужна [`202610230001_add_offer_status.sql`](supabase/migrations/202610230001_add_offer_status.sql). Миграции применяются владельцем проекта через SQL Editor. После обновления перезапустите локальный парсер.
   Для трёх вкладок лидов и возврата из звонков выполните [`202611180003_call_queue_views.sql`](supabase/migrations/202611180003_call_queue_views.sql).
   Для счётчика рассылки по статусу «Новый» и приоритету «Обычный» выполните [`202611180004_mailing_eligibility.sql`](supabase/migrations/202611180004_mailing_eligibility.sql).
   Для отметки отправки сообщения и удаления устаревших статусов выполните [`202611180005_mailing_card_actions.sql`](supabase/migrations/202611180005_mailing_card_actions.sql).
   Для снятия лимита участников выполните [`202611180006_remove_team_member_limit.sql`](supabase/migrations/202611180006_remove_team_member_limit.sql).
   Для кабинетов сотрудников, общей активности и учёта заработка выполните [`202611190001_employee_analytics.sql`](supabase/migrations/202611190001_employee_analytics.sql). Используйте обновлённый интерфейс вместе с этой миграцией.
   Для ручной корректировки рассылок выполните [`202611190002_activity_corrections.sql`](supabase/migrations/202611190002_activity_corrections.sql).
   Для корректировки по дате выполните [`202611190003_daily_activity_corrections.sql`](supabase/migrations/202611190003_daily_activity_corrections.sql).
   Для лидерборда рассылок выполните [`202611190004_mailing_leaderboard.sql`](supabase/migrations/202611190004_mailing_leaderboard.sql).
4. Откройте `Authentication → Users`. Создайте отдельного пользователя с email и паролем для каждого участника. Если интерфейс предлагает автоматическое подтверждение пользователя, оставьте его включённым. Это аккаунты CRM, а не пароли от панели Supabase. После этого рекомендуется отключить публичную регистрацию новых пользователей в настройках Email-провайдера: приложению она не нужна.
5. Откройте `Connect` или `Settings → API Keys` и скопируйте `Project URL` вида `https://xxxxx.supabase.co` и `Publishable key` вида `sb_publishable_...`. Подойдёт и старый `anon` key.
6. На первом компьютере введите эти параметры, войдите первым аккаунтом и создайте команду. В верхней панели откройте значок участников и скопируйте код команды.
7. Каждый новый участник вводит те же URL и публичный ключ, входит под своим аккаунтом и выбирает `Присоединиться`, используя код команды.

Никогда не вводите в приложение `Secret key` или `service_role` key. Публичный ключ безопасно использовать в браузере: доступ к строкам ограничен авторизацией и Row Level Security из миграции.

## Настройка через `.env` (необязательно)

Скопируйте `.env.example` в `.env` и заполните:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT_REF.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_YOUR_KEY
```

Перезапустите `npm run dev`. Файл `.env` исключён из Git. Publishable key всё равно попадёт в браузерный bundle — это нормально; безопасность обеспечивается RLS, а не сокрытием публичного ключа.

## Как работает совместная работа

- Каждая карточка хранится в PostgreSQL и принадлежит одной команде.
- CRM не ограничивает число участников команды. Каждый аккаунт состоит в одной команде.
- Realtime сообщает второму браузеру о добавлении, изменении и удалении карточки.
- После возврата на вкладку, восстановления интернета и раз в минуту приложение сверяет список с сервером.
- Повторные `SIGNED_IN` и `TOKEN_REFRESHED` для того же пользователя не перезагружают команду и не размонтируют интерфейс: открытые карточки, фильтры и черновики остаются на месте. Команда загружается при смене подключения, пользователя или после создания/присоединения к команде.
- Если два человека одновременно меняли карточку, второй получит сообщение о конфликте, а введённый текст останется в форме.
- При удалении запись исчезает у всех участников команды и сохраняется в базе с признаком `is_deleted`.

## Рассылки, прозвоны и архив

- В разделе «Лиды» вкладка «Все» показывает активные карточки, «Звонки» — очередь прозвона, «Рассылка» — новые карточки с обычным приоритетом вне очереди прозвона. Очередь формируется по статусу «Отложен» и кнопке «Прозвонить» в карточке. Кнопка «Вернуть в общее» сохраняет введённые данные звонка, снимает отметку прозвона и ставит статус «Новый» и открывает «Все». При следующем переходе в «Отложен» автоматическая очередь срабатывает снова.
- В обычной карточке «Проверить Telegram» открывает профиль по российскому номеру. Кнопка «Отметить сообщение» сохраняет отправку, переводит лид в «В работе» и закрывает карточку. Доступность профиля зависит от настроек Telegram.
- Кнопка «Убрать» в карточке перемещает лид в «Архив» и скрывает его из рабочих списков. В архиве доступны поиск, история и восстановление. При повторном импорте база проверяет и архивные карточки.
- Карточка в прозвоне открывает результат звонка, заметки, запись с микрофона, загрузку файла и историю. В записи слышен звук, доступный микрофону устройства. Для доступа к микрофону используется HTTPS или localhost. WebM, Ogg, M4A, WAV и MP3 принимаются до 8 МБ на запись. Сохранённые записи доступны участникам команды и входят в резервную копию PostgreSQL.
- «Статистика» показывает размеры списков без пользовательских фильтров. «Всего» учитывает все карточки, включая архивные. Офферы учитываются отдельно. В звонки входят попытки с указанным результатом, включая «Не дозвонился».

### Кабинеты сотрудников и заработок

- «Отметить сообщение» сохраняет событие с автором, лидом и временем. Активность считается по подтверждённым сообщениям Telegram. «Личный кабинет» показывает данные своего аккаунта. Календарные периоды рассчитываются по времени Волгограда, неделя начинается в понедельник.
- «Статистика» и «Личный кабинет» показывают отдельно указанный общий итог в 56 рассылок. Счётчики по событиям продолжают обновляться автоматически.
- Владелец видит «Лидерборд рассылок» в разделе «Статистика». Рейтинг показывает итоги по сотрудникам за выбранный день, неделю или месяц. Неделя разбита на дни. Рейтинг учитывает подтверждённые отправки и персональные корректировки.
- Владелец команды открывает «Пользователи» и видит участников своей команды, их активность и начисления. В кабинете сотрудника владелец может добавить или исправить начисление в рублях и связать его с лидом. Общий заработок виден владельцу в «Статистика → Активность команды».
- В кабинете сотрудника кнопка «Изменить статистику» добавляет или вычитает рассылки за выбранную дату. Корректировка входит в дневной итог и отображается отдельно от почасовых столбцов. Чтобы отменить начисление заработка, измените его сумму на 0 ₽.
- Чтобы сверить подтверждённый исторический итог 55, владелец открывает «Историческая сверка рассылок», указывает дату и время, к которым относится итог, и проверяет число событий перед сохранением. При 39 событиях добавляется ровно 16. При меньшем числе подтверждённых событий нужен источник итоговых 55 отправок. Сверка сохраняется один раз для команды и влияет только на общий итог за всё время. Если в базу позже внесут подтверждённые события за тот же период, они заменят соответствующую часть корректировки. Персональные показатели и графики строятся по датированным событиям с авторами.
- В «Парсере» флажок «Исключать, если есть сайт» включён по умолчанию. Настройка сохраняется в конкретном пакете и учитывается при отборе и публикации.

Supabase может приостанавливать бесплатный проект после периода бездействия; первое открытие после паузы иногда занимает больше времени.

## Структура веб-приложения

- `src/App.tsx` — подключение, восстановление сессии и загрузка команды;
- `src/components/AuthScreens.tsx` — первый запуск, вход, создание и подключение к команде;
- `src/components/Dashboard.tsx` — оболочка, навигация и обзор;
- `src/components/LeadsPage.tsx` — список, фильтры и формы карточек;
- `src/hooks/useLeads.ts` — CRUD, Realtime, сверка и защита от конфликтов;
- `src/imports/` — общие типы, нормализация, дедупликация, филиальные правила и порт сервиса импорта;
- `local-parser/` — отдельный Node.js companion: локальный видимый Chromium, SQLite-хранилище, ограниченный loopback API и адаптер 2ГИС;
- `src/styles.css` — адаптивный интерфейс;
- `supabase/migrations/` — схема базы, RLS, RPC и публикация Realtime.

Запуски и промежуточные карточки лежат в SQLite на компьютере, где запущен сбор, по пути `%LOCALAPPDATA%\PahotaCRM\imports.sqlite`. До нажатия пользователем «Подтвердить и опубликовать» основная таблица лидов не меняется. После подтверждения бsраузер вызывает RPC через действующую авторизованную Supabase-сессию; локальный процесс не получает Supabase credentials.

Для проверки доменной логики импорта запустите `npm test`. Подключение реального источника данных и разрешённый срок хранения его результатов настраиваются отдельно; миграция сама по себе не выполняет сбор.

## Фильтр сайта и браузерная проверка

В списке лидов фильтр «Сайт» предлагает «Все», «Есть сайт» и «Нет сайта». Он сочетается с поиском, нишей, статусом и приоритетом; выбранные фильтры сохраняются в прежнем ключе локального хранилища. Используются существующие `website` и `website_status`: HTTP(S) URL или домен без протокола означает наличие сайта, соцсети и Taplink исключаются. Если URL отсутствует, прежние ручные отметки «Есть сайт» и «Слабый сайт» учитываются как наличие сайта; пустое поле без такой отметки означает отсутствие сайта. Новых полей в базе нет.

Регрессия в Chromium использует настоящий React и Supabase SDK с изолированным API и не обращается к рабочим данным. Нужны зависимости `local-parser` и установленный через `npm --prefix local-parser run install:browser` Chromium. В PowerShell запустите тестовый dev-сервер:

```powershell
$env:VITE_SUPABASE_URL='https://crm-regression.supabase.co'
$env:VITE_SUPABASE_PUBLISHABLE_KEY='sb_publishable_crm_regression_test_only'
npm run dev -- --port 5175 --strictPort
```

В другом терминале выполните `node tests/crm.browser.mjs`. Сценарии включают рабочие списки, архив, статистику и запись через MediaRecorder с тестовым микрофоном Chromium. Для проверки реального переключения вкладок и сворачивания окна выполните `node tests/crm.browser.mjs --headed`. Миграции, права команд и сохранность данных после перезапуска PostgreSQL проверяет `npm test` в изолированной базе.

Для production повторите `npm run build` с теми же тестовыми переменными, запустите `npm run preview -- --port 4175 --strictPort`, затем задайте `$env:CRM_TEST_URL='http://127.0.0.1:4175'` и выполните тот же браузерный тест. После проверки удалите тестовые переменные из терминала (`Remove-Item Env:VITE_SUPABASE_URL,Env:VITE_SUPABASE_PUBLISHABLE_KEY,Env:CRM_TEST_URL -ErrorAction SilentlyContinue`), чтобы обычная сборка использовала ваши н~астройки.
